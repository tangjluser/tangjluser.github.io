# hot100 解题思路
## [两数之和](https://leetcode.cn/problems/two-sum/)

先在哈希表中找 target - x存不存在 如果不存在就把x插入哈希表

>为什么用哈希表？

因为哈希表的 查询是 o（1）的 但是哈希表里的数据是无序的 需要和 map区分开

>那为什么是插入x呢？ 

因为我是从左到右去遍历的，遍历到x的时候，表中没有 target - x 那我往后面遍历的时候 遍历到 target - x的时候 就可以查到表中有 x 这样就可以 o（n）的解决了

## [字母异位词分组](https://leetcode.cn/problems/group-anagrams/)

遇到每个单词，先按从小到大排序，然后存入哈希表，下次来就是o（1）的查询

## [最长连续序列](https://leetcode.cn/problems/longest-consecutive-sequence/)

先将每个数存入哈希表，为了去重
然后遍历哈希表，遍历一个数，就先看这个数-1在不在哈希表，不在就以它为起点，一直看这个数+1有没有，有就重复，重复的长度就是连续序列的长度

>为什么要先看 这个数-1 在不在？

为了防止重复判断，因为我每次都找的是这个连续序列的起点

## [三数之和](https://leetcode.cn/problems/3sum/)


因为不要求顺序，而且只是输出3元组是哪三个数，不是输出下标
所以先从小到大排序
然后从1-n遍历 第一个数x
然后从 x 之后 到 n 遍历第二个数y
然后这个时候是关键  假设现在有个 k
x + y + k = 0
然后我接下来遍历 y‘ 
但是 y’ > y 
所以 x + y‘ + k > 0 所以 k 就要变小
那一开始 k 不就可以从右往左遍历？ 就是对于 x固定的时候
所以就变成
```C++
for (int i=0;i<len;i++)
	for (int j=i+1;j<k;j++)
		while(a[i]+a[j]+a[k]>0 && k>j+1)
```
这样总体的复杂度就是 o($n^2$)

## [接雨水](https://leetcode.cn/problems/trapping-rain-water/)

本质是从动态规划的思想优化到双指针
动态规划就是 
从左到右求一遍 到i位置的 lmax 然后存到i位置
从右到左求一遍 到i位置的 rmax 然后存到i位置
然后对于每个i 那就是 lmaxi 和 rmaxi 取小 然后 - height[i]
那优化成双指针就是
L在左，R在右
然后维护 Lmax，Rmax
然后左边小更新左边
右边小更新右边 （等号依旧放左 放右 都没区别 可能争对不同的数据 有快慢区别 但是对答案没影响）
```c++
while(l<r){
            lmax = max(lmax,h[l]);
            rmax = max(rmax,h[r]);
            if(lmax < rmax){
                ans += (lmax - h[l]);
                l++;
            }else {
                ans += (rmax - h[r]);
                r--;
            }
        }
```


## [无重复字符的最长子串](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)

核心在于  假设我现在找到一个 字串了
左端点是 L 右端点是R
如果右边的下一个 和里面不重复 那肯定加进来
那如果右边的重复了，我只需要 L 右移就可以了
[L , R] 不重复  - > [L+1 , R] 也肯定是不重复的，然后就可以继续判断了 整体的复杂度就是 o(n)了
为了高校的实现判断 新的这个字母在不在 这个区间内，我们用到哈希集合

>为什么这里用的是 r + 1  而不是 r 呢？

因为一开始整个字符串都没有进行过判断 也就是 r的 初值是 -1
那我接下来要判断的 就是 r + 1 了
并且我接下来要判断的下标 肯定要在 整个字符串的 范围内，所以 r + 1 < len
然后如何去进行判断 就是 写这样一个for  从 第0个位置开始 就是相当于把每个位置都当作起点判断一下
```C++
unordered_set<char> mp;
for (int i=0;i<s.size();i++){
    if(i != 0){
        st.erase(s[i-1]);
    }
    while(r+1<s.size() && st.count(s[r+1]) == 0){
        st.insert(s[r+1]);
        r++;
    }
    ans = max(ans,r-i+1);
} 
```

 >那如果去快速的判断呢？

## [和为 K 的子数组](https://leetcode.cn/problems/subarray-sum-equals-k/)

这道题 思路很妙
首先看到这题，我们会很自然的想到枚举 每个 i 和 j
```C++
for (int i=0;i<len;i++){
	sum = 0;
	for (int j=i;j<len;j++){
		sum += a[j];
		if(sum == k){
			cnt++;
		}
	}
}
```
这个时间复杂度 是 o($n^2$) 的 那数据量一大 就 超时了
那主要超时的时间 都花在计算  从 i - > j 的 和上了

>那有没有快速计算一段区间的和的方法呢？ 

前缀和，那如何用上前缀和呢，总不能是 sum += a[j] 那里用吧，那时间复杂度也没变化呀
是的，所以这里就是重点，如何用前缀和
我们用前缀和就是为了快速判断 
pre[j] - pre[i-1] == k
移项
pre[j] = pre[i-1] - k
理解这个式子 也就是 在当前 j 的位置上 前面有没有出现过 pre[i-1] - k 这个值 （i < j）
那如何快速找前面出现过的值，我们就可以使用哈希表（这个我们在 第一题 学习过了）
所以最后整体的思路就是
每到一个数，我就加入前缀和，并加入哈希表
然后再来判断哈希表中有没有出现过 pre[i] - k  (这里的i 你需要理解成 当前位置)
如果由于有负数的存在，所以前面可能会出现 多个 pre[i] - k 这个点也需要注意

## [合并区间](https://leetcode.cn/problems/merge-intervals/)

首先看到题目，毫无疑问会想到排序，按第一关键字升序
然后就是遍历整个数组，如果当前答案数组中的最后一个的 右端点 > 遍历的这个数组的 左端点
那答案数组中的 右端点就更新成二者中的较大者
```cpp
if (!merged.size() || merged.back()[1] < L) {
	merged.push_back({L, R});
}
else {
	merged.back()[1] = max(merged.back()[1], R);
}
```
然后这里新学到一个 就是 vector.back() 是可以对原来的值 做直接修改的

## [搜索二维矩阵 II](https://leetcode.cn/problems/search-a-2d-matrix-ii/)

一种直观的方法，我对一行都进行二分
这样的复杂度是 o($m*log(n)$)
但是题解提供了一种新思路
就是 我每次 枚举的范围是 左下角 是 （m-1,0) 右上角是 （0，n-1）的长方形
然后 i j 初值就是 右上角
然后开始判断$a[i][j]$是否满足条件
如果 < target
那就 i++ (我这个位置小了，但是我后面可能有比你大的，所以往下走)
如果 > target
那就 j-- (这个位置都比你大了，而且我往下走还是升序的，那就只能往前退了)
相等就输出答案了，整个图都遍历完了，那就没了
这个的复杂度会优很多，基本上是走一个折线的对角线的复杂度，没去细算
